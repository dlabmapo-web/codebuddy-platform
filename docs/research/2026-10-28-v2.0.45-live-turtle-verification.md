# v2.0.45 live public Turtle verification

Date: 2026-10-28, Asia/Seoul. Production revision:
`e41050757eedaf752c1142643221802985bc6578`.

The [release workflow](https://github.com/dlabmapo-web/codebuddy-platform/actions/runs/40636085498)
completed successfully after human Production approval. Studio, API, judge
worker and Caddy were inspected healthy. The supplied classroom code opened
the public workspace and the new Cove toolbar was visibly deployed.

## Findings

Five valid runs observed the first new colored line at approximately
**2.7–3.1 seconds**, with a **3.01 s sample median of first-positive capture
completion times**. These are five diagnostic observations including browser
control/screenshot overhead, not a p95 or classroom-load guarantee.

A separate valid attempt was still queued with no line after **8.04 seconds**
of capture after the click call returned. Read-only broker inspection showed
**one execution slot**, two open sessions and one allocated guest while this
audit was queued. Another session occupied the slot. Only this audit's queued
request was cancelled; the other session was not stopped. The slot subsequently
became idle and five drawings succeeded.

The browser engine switches are both **false**. Public Turtle still uses the
existing server runtime, with **warm mode disabled**. The toolbar has improved;
startup remains roughly three seconds when a slot is available. The previous
v2.0.44 diagnostic observed about 3.0–3.2 seconds in three runs. This small,
uncontrolled comparison does not establish a material runtime speed gain.
No production runtime, capacity, worker count, flag, PIN or broker setting
was changed for this verification.

## Timing method

A fresh audit tab had no existing guest grant; the supplied code created the
audit's access. The valid synthetic program was:

```python
from turtle import pensize
from custom import *
speed(0)
color("red")  # Alternate red, blue and green between runs.
pensize(10)
TForward(200)
```

`speed(0)` removes drawing animation solely to measure startup. The helper is
the real shipped `TForward`. Product defaults were not changed. The first
successful run followed a stopped queued attempt; the following four Run clicks
retired the preceding displayed drawing, so those include normal teardown.

CUA captured the visible Drawing region as JPEGs for eight seconds per attempt.
Offline Pillow analysis required at least 100 pixels of the new hue spanning
at least 60 horizontal pixels in the line band, 32–130 pixels to the right of
its center and ±24 pixels vertically. This excludes the initial turtle cursor.
All five baselines lacked the next run's target line. Actual red, blue and
green drawings were visually inspected. No browser canvas pixel API or hidden
application state was read.

The capture begins before the click tool call, whose dispatch/return duration
was 277–428 ms for successful attempts. The conservative bounds below allow
for both that uncertainty and screenshot timing: lower = preceding negative
capture start minus click-call completion; upper = first-positive capture
completion minus click-call start. No claim is made about an exact physical
pixel presentation timestamp.

| Successful run | Color | Conservative click-to-line bounds | First-positive observation |
| --- | --- | ---: | ---: |
| 1 (attempt 3) | Red | 2.18–2.74 s | 2.741 s |
| 2 (attempt 4) | Blue | 2.70–3.11 s | 3.111 s |
| 3 (attempt 5) | Green | 2.62–3.02 s | 3.018 s |
| 4 (attempt 6) | Red | 2.62–3.01 s | 3.010 s |
| 5 (attempt 7) | Blue | 2.47–2.88 s | 2.876 s |

Before these, attempt 1 used an invalid test script: `pensize` was omitted from
the imports (`custom.__all__` does not export it). Its NameError was retained
and classified as a test-script error, not a startup measurement. Attempt 2
used the corrected script and was the queued attempt described above.
Preparatory editor-selector failures happened before Run and are not platform
latency samples; visible editor clicking/pasting was used successfully.
