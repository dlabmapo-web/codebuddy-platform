# Production Email Operations

This runbook configures Cove Studio v2 transactional email without changing the
existing MVP records on `coveedu.com`. Resend sends mail; Contabo does not run an
SMTP server.

## Production addresses

| Purpose | Value |
|---|---|
| Home | `https://coveedu.com` |
| Cove Studio v2 | `https://cs.coveedu.com` |
| API | `https://api.coveedu.com` |
| Sending domain | `mail.coveedu.com` |
| Sender | `Cove Studio <no-reply@mail.coveedu.com>` |
| Webhook | `https://api.coveedu.com/api/webhooks/email` |

## Secret ownership

| Secret | Create/store | Consumer |
|---|---|---|
| `Cove Studio Production API` key | Resend; Contabo secret environment | NestJS invitation sender |
| `Cove Studio Supabase SMTP` key | Resend; Supabase SMTP settings only | Supabase Auth mail |
| Webhook signing secret | Resend webhook; Contabo secret environment | NestJS webhook verifier |

Never paste these values into Git, a `NEXT_PUBLIC_*` variable, a screenshot, or
an application log. The two Resend keys must have sending-only access restricted
to `mail.coveedu.com`.

## 1. Verify the sending domain through Gabia

1. In Resend, add the domain `mail.coveedu.com`.
2. Copy the exact SPF, DKIM, and MX records generated by Resend.
3. In Gabia DNS, add only those new records. Preserve every existing root,
   `www`, and MVP record.
4. Do not create two SPF TXT records at the same hostname. Merge only if Gabia
   shows an existing SPF value for that exact hostname.
5. If Gabia appends the zone name to an MX target, enter Resend's target with a
   trailing dot.
6. Wait until Resend reports SPF and DKIM as verified.
7. Add DMARC for the sending subdomain in monitoring mode first. Move to an
   enforcement policy only after reviewing real delivery evidence.

Do not create production sending keys before the domain is verified.

## 2. Create separate Resend credentials

Create these two keys in Resend:

- `Cove Studio Production API`: sending-only, restricted to
  `mail.coveedu.com`.
- `Cove Studio Supabase SMTP`: sending-only, restricted to
  `mail.coveedu.com`.

Copy each key once into its destination. Resend does not show the complete key
again. The Supabase SMTP key must not be placed on Contabo.

## 3. Configure Supabase Auth

In Supabase custom SMTP settings use:

```text
Host: smtp.resend.com
Port: 465
Username: resend
Password: <Cove Studio Supabase SMTP key>
Sender name: Cove Studio
Sender email: no-reply@mail.coveedu.com
```

Disable Resend click and open tracking for this transactional stream. Rewritten
links can interfere with one-time Supabase authentication URLs.

Set the Auth Site URL to `https://cs.coveedu.com`. Add these exact production
redirect URLs to the allowlist:

```text
https://cs.coveedu.com/auth/callback
https://cs.coveedu.com/auth/recovery/confirm
```

Do not add a wildcard production redirect. The signup/OAuth flow uses the first
route; the Cove password-recovery flow uses the second.

The recovery email template must link to Cove's confirmation interstitial with
Supabase's token hash and the fixed recovery type:

```text
https://cs.coveedu.com/auth/recovery/confirm?token_hash={{ .TokenHash }}&type=recovery
```

Test the rendered link in a controlled account before launch; template variable
syntax is owned by Supabase and should be copied from its current dashboard
documentation if the editor reports a validation error.

## 4. Configure Contabo

Place these values in the API process's server-only environment:

```dotenv
NODE_ENV=production
WEB_ORIGIN=https://cs.coveedu.com
EMAIL_API_KEY=re_replace_with_cove_api_sending_key
EMAIL_FROM="Cove Studio <no-reply@mail.coveedu.com>"
EMAIL_WEBHOOK_SECRET=whsec_replace_after_webhook_creation
```

Use the complete API environment list in `packages/api/.env.example`. The API
will refuse to start in production if any of the three email settings is
missing. Permit outbound HTTPS from NestJS. No inbound or outbound SMTP port is
needed on Contabo; Redis and internal application ports remain private.

## 5. Register the webhook

Only after `https://api.coveedu.com` is deployed with valid HTTPS, create the
Resend webhook:

```text
https://api.coveedu.com/api/webhooks/email
```

Subscribe to:

- `email.sent`
- `email.delivered`
- `email.bounced`
- `email.failed`
- `email.suppressed`
- `email.complained`

`email.delivery_delayed` may also be selected for diagnostics. Cove
acknowledges it without falsely marking the message as failed. Copy the webhook
signing secret into `EMAIL_WEBHOOK_SECRET`, restart the API, and confirm an
unsigned request is rejected.

## 6. Launch verification

Use controlled inboxes and complete every check before public launch:

1. Confirm the API health endpoint is available through HTTPS.
2. Send one academy invitation. Resend acceptance must record `SENT`; only the
   signed delivered webhook may record `DELIVERED`.
3. Replay the same webhook and confirm there is no second transition.
4. Exercise a controlled bounce and confirm Cove records the adverse outcome.
5. Sign up a new password account and complete email confirmation.
6. Request password recovery and complete the Cove recovery flow.
7. Resend an academy invitation; the new link must work and the old link must
   be rejected.
8. Confirm all email links use `https://cs.coveedu.com`.
9. Inspect API logs for secrets, full recipient addresses, or invitation links.

## Rotation and incident response

For an API or SMTP key, create a replacement with the same restricted access,
deploy it to its sole consumer, perform a controlled send, and only then revoke
the old key. This avoids downtime and preserves separate audit trails.

For the webhook secret, create/update the endpoint in Resend, deploy the new
secret to Contabo immediately, restart the API, and send a test event. During a
mismatch, logs show signature rejection and no delivery state is changed.

Operational signals:

- `transport_error`, `provider_429`, or `provider_5xx`: provider/network issue;
- `provider_restricted_api_key` or another authentication code: key scope or
  deployment configuration issue;
- `provider_invalid_from_address`: sender/domain configuration issue;
- `suppressed`, `complained`, or a `bounce_*` code: recipient/provider adverse
  evidence; do not blindly retry;
- repeated bad-signature logs: webhook secret mismatch or unsolicited traffic.

Resend webhooks are at-least-once and can arrive out of order. Replay from the
Resend dashboard is safe: Cove deduplicates by `svix-id` and prevents ordinary
state regression while retaining later bounce, complaint, or suppression
evidence.
