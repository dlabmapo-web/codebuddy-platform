# v2.0.46 live Brython Turtle verification

Date: 2026-10-28, Asia/Seoul. Production revision:
`0ae56bc6ce882ce1fad5730c1bc19e5d8677c238`.

**Brython is now enabled and verified in the live public Turtle workspace for
new Dlab-Mapo grants.** All five synthetic ready-runtime startup runs succeeded.
Reported click-to-first-stroke durations were **239.8–365.6 ms**, median
**300.7 ms**, including live admission. Independent screenshots first observed
the new line within **0.714–0.848 s**, median **0.764 s**, including remote
control and screenshot overhead.

The earlier v2.0.45 server-engine diagnostic observed **2.7–3.1 s**, median
**3.01 s**, with a separately queued attempt exceeding eight seconds. This
small comparison shows a substantial improvement on the tested device and
connection. It is not a controlled classroom trial, p95 or capacity guarantee.

## Timing method and results

A new audit visitor entered the supplied code through the real public form.
The actual visible Drawing iframe loaded the production runtime origin and
pinned artifact above. No authenticated account or course workspace was used.

The same valid helper fixture as the earlier live audit was run five times,
alternating red, blue and green to exclude retained frames:

```python
from turtle import pensize
from custom import *
speed(0)
color("red")
pensize(10)
TForward(200)
```

`speed(0)` isolates startup in this test program; shipped teaching defaults were
not changed. Runs began with a prepared interpreter. Cold download/preparation
and rapid reruns before spare preparation are not measured by these numbers.

| Run | Color | Browser-reported first stroke | Live admission | First positive screenshot |
| --- | --- | ---: | ---: | ---: |
| 1 | red | 300.7 ms | 250.1 ms | 0.764 s |
| 2 | blue | 365.6 ms | 279.7 ms | 0.848 s |
| 3 | green | 331.7 ms | 233.7 ms | 0.829 s |
| 4 | red | 239.8 ms | 173.0 ms | 0.716 s |
| 5 | blue | 245.6 ms | 190.1 ms | 0.714 s |

The reported values were read from the live toolbar's DOM duration attributes;
they end at the validated renderer stroke/animation-frame signal, not certified
physical presentation. They are not presented as independent pixel timestamps.

Independently, CUA repeatedly captured the visible Drawing region and offline
Pillow hue analysis required at least 100 new-color pixels spanning at least
60 horizontal pixels in the expected line band. The initial cursor is excluded.
Every baseline lacked the next color's line. First-positive and preceding
screenshots are retained. The screenshot clock starts before the click call;
click dispatch/return took 465–556 ms. Conservative bounds and all capture
start/end timings are retained in the raw JSON. These observations include
control/capture delay and are upper observations, not exact rendering latency.

Before run three, a visible-editor assertion ran before Monaco redrew the new
source. A screenshot confirmed the correct green code before Run. No extra Run
was sent and no runtime latency sample was discarded.

## Functional checks and cleanup

- Normal default-animation square completed with `TForward` and `TLeft`.
- A computing infinite loop left the parent controls responsive; Stop returned
  the UI to Stopped. One control-to-observed-STOPPED sample was 432 ms including
  CUA overhead, not a worker-acknowledgement timing or p95 acceptance result.
- Unsupported `input()` exposed the explicit full-Python action. It was never
  clicked. A supported blue helper spiral subsequently completed in Brython.
- Read-only broker snapshots before, after the five timings and after cleanup
  showed zero open native sessions and zero allocated guests. Supported audit
  execution stayed on the browser path; the native broker retained its limits.
- The audit visitor exited through More options → Exit. The empty code form
  was visibly restored; only the audit's grant was revoked. Audit tabs closed.
- No official submissions, grade records, curriculum or account memberships
  were created or edited by this audit. Only synthetic public guest code ran.

Existing server-mode visitors retain their original engine. Use More options →
Exit and enter the classroom code again to obtain a new browser-mode grant.
Refreshing an existing native grant alone preserves its engine.

Windows/Chromebook/iPad coverage, controlled cold/cache readiness, 100-run
full-path p95 and twenty real student devices remain open acceptance work.
The earlier local twenty-admission fixture proves only the isolated admission
path, not live classroom capacity. Full Python remains an explicit server path
with its existing one-slot capacity.
