# How Cove records mistakes and serves feedback

This is the proposed implementation contract for the [student workflow](2026-11-25-cove-ai-learning-assistant-design.md). The record names below describe new storage. Cove already has submissions, grading cases, solve sessions and authored hints in its [Prisma schema](../../../packages/api/prisma/schema.prisma).

## Durable records

| Record | Identity and contents |
| --- | --- |
| Exercise context | An immutable, shared snapshot of the student-visible statement, input/output formats, constraints and safe public examples. Key it by academy, material, grading revision and a digest of the teaching text and examples. At submission admission, freeze the context reference and eligibility. A text-only edit can change the advice even if the grading revision stays the same. |
| Mistake occurrence | One private row per eligible failed submission, unique on submission ID. Keep context ID, programming language, time, analysis state and observed failure categories. Reference the submission for the student's code and recorded case outcomes. Store all observed case positions/outcomes privately, including unclassified evidence. A skipped case is unobserved. Multiple cases with the same symptom still count as one occurrence of that pattern in this attempt. |
| Reusable pattern and notes | One pattern per context, programming language and stable evidence rule (for example, `public_exact_output_case_only`). Unique note slot per pattern, locale, kind (hint or feedback) and hint level. Use a separate exercise-wide slot for general hints. Store versioned text, allowed evidence placeholders, provenance, rule/prompt/model version and active/retired state. Enforce uniqueness for exercise-wide slots as well as pattern slots. Link occurrences to patterns by a unique occurrence–pattern pair. |
| Help delivery | One private reply per student request ID. Store action, scope, solve session or submission, locale, exact delivered text, source and note version where available. A repeated request with the same payload returns the original reply. Reject reuse of that ID with a different payload. On a new request, respect the current note version. Retain delivery history according to the academy's student-record policy. |

Use the existing owner and class scope for private reads. Remove linked private observations and deliveries through the same deletion lifecycle as their student records. Shared notes contain general teaching text with placeholders filled only from the current student's public evidence. Academy course copies start with their own AI history. Keep AI notes in their own tables. Both [course saves](../../../packages/api/src/content/course.service.ts) and [imports](../../../packages/api/src/content/import/content-import.service.ts) replace authored hint rows.

## Capture, including when nobody clicks

1. At [submission admission](../../../packages/api/src/learn/submission.service.ts), use the existing joined read and transaction to attach the eligible context. Check student learning scope, exercise flag, programming exercise type, `AUTOMATIC` policy and absence of an exam. An ordinary non-exam exercise is distinct from Cove's `PRACTICE_ONLY` enum, which rejects official submission. Cache identical contexts by their unique key. Existing submissions can lack a context reference.
2. The existing [judge](../../../packages/api/src/judge/grading.service.ts) commits the official verdict and cases. Treat that durable record as the source of work. An after-commit notification can wake a separate assistant worker. An indexed, batched reconciliation query also finds eligible terminal failures missing an occurrence, including late-finishing submissions and lost notifications. Exclude repairs, staff practice, aborted runs, infrastructure faults and cancellations. The judge never waits for inference.
3. Upsert an occurrence before attempting inference. Record visible symptoms even with no matching rule. Generate reusable notes in the background for supported patterns, including attempts where nobody requests help. Track pending, leased, ready, unclassified and retryable analysis. Reclaim expired leases and scan unfinished analysis separately from missing occurrences. The interactive path may race the worker. Claim a note slot with an expiring lease and finish with a version-checked write. Use unique keys for occurrence links and deliveries and protect retired or teacher-edited slots from automatic overwrite.
4. Link a delivery to the first later genuine submission by the same student in the same class, material and context, using server timestamps and a stable ID tie-breaker. Keep an unknown outcome if the student never retries. An early hint can attach to an owned solve session, then to the following submission. A passed submission may resolve an earlier attempt without creating a new mistake.

For historical attempts, backfill in restartable batches only where scope, eligibility at the time and context can be established. Preserve unknown or legacy evidence in its original submission. A current exercise toggle or a new problem statement cannot establish what a student saw last term.

## Request and model contract

| Proposed operation | Server behavior |
| --- | --- |
| `getHint` | Receive academy, class, material, locale, request ID and optional owned solve session/current visible draft. Resolve access and the current exercise context server-side. Use the next authored hint first, then an applicable bank hint. For an empty bank, generate a small next step from the public task. Advance the hint level once per distinct request. |
| `explainResult` | Receive academy, material, submission ID, locale and request ID. Load the owned submission, verify exercise scope and eligibility, and use its frozen context. Only offer an explanation for a final student failure. A matching active feedback note can be rendered directly using this submission's public values. |
| `reviseNote` / `retireNote` | Require existing course-content edit authority for this academy and material, validate the note scope, and check the expected version. Audit author and time. A retirement suppresses regeneration of the same slot. |

Resolve current access and enablement on every student operation, including replay. Derive identity, result, grading policy and evidence on the server. An unauthorized or unreachable submission gets the same response as a missing one. Render delivered strings as plain text and cap code, output and reply sizes. Reuse the sample visibility logic in [submission results](../../../packages/api/src/learn/submission.service.ts). Project only public case values, approved diagnostic categories and the student's own visible code. Hidden case payloads, private project files, solutions, raw logs, names and provider secrets never enter a prompt or shared note.

Use a server-side model adapter with configurable endpoint, model ID, credentials, timeout and concurrency. Keep student code inside a delimited data field. Give the model an action, locale, context, evidence IDs and valid note candidates. Ask for a short observation and one next step in the requested language, with evidence IDs for the observation. Reject malformed output, unsupported evidence references and replies that contain a complete solution. Render a reviewed fallback on validation failure or timeout. A hidden-only failure can get “Try a small input you can work through by hand. What would you expect your program to print?”

**Automatic reuse rule.** The server chooses the pattern. For example, activate a case-only mismatch rule only on an applicable equality comparator, a genuine wrong public output, complete visible values and a difference explained by letter case after the grader's normalization. Use audited, parameterized wording for the reusable observation and validate its placeholders. The first release can persist model-selected combinations of reviewed teaching phrases for that rule. A model-written hypothesis can guide a private question. Novel free text or a confidence score alone cannot create a shared diagnosis. This makes automatic reuse possible without assigning teachers an approval queue.

For a previously unseen logic mistake, Cove can still share what the evidence establishes. For example, if the larger-number exercise returns the smaller input on a public case, save the observed relationship and a hint to trace the selected value. Many different implementations can produce that result. Keep a claim like “your branches are reversed” specific to the current attempt unless a separate rule establishes it. As the team adds evidence rules, replay stored unclassified occurrences against the new rule version. Each new match enriches the bank while preserving the original attempt and the answer already shown.

Exercise-wide hints can be generated from public instructions without a student draft. Save reusable wording after checking that it fits the exercise, hint level and approved teaching phrases. If a draft helped personalize a reply, keep its exact text in that student's delivery. Create the shared version from the public context and validated pattern alone. For either action, persist the validated reply before returning it so an interrupted connection can replay the same result. Record creation and any client acknowledgement separately if measuring whether a student actually saw the message.
