# Reliable academy-to-library course copies

- **Date** 2026-11-20
- **Status** Proposed for review
- **Base** `origin/feat/cove-studio-v2` at `05bf4436`

## Goal

A platform admin can copy a complete academy course into an independent, unpublished library draft. The copy preserves authored content, grading behavior, order, required flags, and the visibility of modules, lectures, and materials, including content under hidden ancestors. When part of a course cannot be copied faithfully, the preview identifies the item, the specific failure, and the action that resolves it. A failed copy leaves the source and destination unchanged.

This design extends the existing [academy-to-library copy](2026-10-13-academy-course-to-library-design.md) and applies to both [entry points](2026-10-13-library-academy-picker-design.md). The destination retains copy provenance and starts at revision 1. Class assignments, enrollments, student work, progress, grading history, and academy adoption and sync state stay outside the snapshot. Existing platform and academy permissions continue to apply.

## Production incident and v2 audit

The live preview for Mapo Campus’s `[DC-C-2] C언어 심화 라이브러리`, revision 318, blocked on 증감 연산자, 논리 연산자, and 지역변수와 전역변수 and their three hidden `[삭제]` copies. All six showed “Invalid material definition.” The browser confirmed the affected titles and disabled action. The exact rejected fields in production remain unverified.

| Verified in v2 | Impact |
| --- | --- |
| `libraryImportBlockers` reduces schema failures, missing subtype rows, and several reference problems to `INVALID_DEFINITION`. The preview returns only an item ID, title, and reason. | An admin cannot tell from the dialog whether to edit a definition, restore an attachment, or investigate inconsistent records. |
| `readCourseImportPreview` fetches subtype rows by the material’s declared type. `courseCopyInclude` loads every attached subtype, and the copier writes several of those relations independently of type. | A legacy supplementary attachment on another material type can be absent from preview checks and appear at copy time. |
| `saveManualSchema` validates the parsed multiple-choice value, which can strip extra keys. The copier parses the original JSON with the strict choice schema to remap IDs. | A choice with an extra top-level property can pass preview and fail during copy. The correct handling depends on whether the property is known to be inert. |
| The programming preview reads the quiz JSON alone. The copier also resolves linked PDFs and builds private solution rows. It carries multi-file projects and stored starter bundles without checking their equivalence. | A bad PDF link or solution payload can fail only after submission. A stale multi-file projection or unresolved exercise image can reach a copied course. |
| The explanation validator calls the sanitizer and discards its output. The video validator uses the base config schema, which omits authoring checks for duplicate caption languages and supplementary-only scoring. Asset lock errors can also lose item context. | A successful preview leaves gaps between copyability and the content the destination will actually render or enforce. |

Relevant code is in [the preview reader](../../../packages/api/src/content/library/course-import-preview.ts), [the validator](../../../packages/api/src/content/library/library-import-validation.ts), [the tree copier](../../../packages/api/src/content/library/course-tree-copy.ts), and [the import service](../../../packages/api/src/platform/platform-library-import.service.ts).

## Approaches considered

| Approach | Trade-off |
| --- | --- |
| **Shared validation and lossless compatibility handling** | Fixes disagreements between preview and write. Known older representations can be copied safely, and ambiguous data gets a targeted blocker. This requires explicit coverage of each supported material. |
| Diagnostics with source repair for every invalid value | Gives admins actionable errors quickly. Every compatibility mismatch still requires someone with source-edit permissions to repair the academy course. |
| Partial copy with explicitly excluded items | Can create a draft sooner. Excluding materials can break dependencies, required work, and hidden content preservation. It would require a separate product decision and interaction. |

Use shared validation and lossless compatibility handling. Preserve the current all-or-nothing workflow.

## Validation and copy behavior

1. Authorize preview and import through the existing platform and source-academy permissions. Both readers resolve the same course scope and enumerate the complete tree and every supported attached subtype. A material must have its declared primary subtype. Preserve a supported legacy PDF or video attachment alongside it. Report unsupported combinations and orphaned or mismatched data.
2. Introduce one copy validator and preparation path in `packages/api/src/content/library/`. It uses the current domain parsers, serializers, sanitizers, and relationship rules where applicable, plus explicit compatibility rules for persisted older data. Preview receives safe diagnostics. Import receives those same diagnostics plus the validated authored values for constructing destination rows. The copier consumes prepared values, including definitions it remaps, so it never reparses the original JSON under different rules.
3. Treat a supported persisted representation as copyable when it produces the same effective content and grading. Examples include resolving a versioned default already applied by the runtime, or materializing a legacy solution into the current representation when an existing reader or migration establishes the same answer. Each compatibility rule needs a fixture proving that equivalence. Use the existing trusted authoring and rendering policy for rich text, and copy the same validated/sanitized representation used to check its asset references. Block when required content disappears under sanitization or when a lossless interpretation is uncertain.
4. Keep valid incomplete content copyable. A programming exercise being authored without tests, or with intentionally manual or practice-only submission, follows current readiness rules. Diagnose a genuine readiness issue as a warning if the existing authoring and publication flows can safely handle the draft. Persisted content that already works in the current runtime may exceed newer editor request limits. Retain the existing large-course copy coverage and avoid blanket application of new-save limits to stored rows.
5. Block genuine broken content with a repair action. Examples include a missing required subtype, ambiguous answer keys, invalid executable definitions, missing or unauthorized assets, or an unresolved reference outside the source course. Preserve existing publication and delivery guards for warnings such as a hidden PDF required by a visible exercise. A supported hidden item goes through the same integrity checks as a visible one.
6. Write the unpublished draft, authored descendants, import receipt, and audit event in one transaction. Generate new curriculum IDs and fresh revisions as today. Preserve stable authored ordering and keys, remap typed internal links after allocating the new IDs, and keep existing immutable asset references under the same access and retention rules. Preserve the source academy’s revision and content even when destination values are normalized.

### Shared assets and links

- Collect asset and caption IDs across the snapshot and resolve each kind in one batched query. Validate every reference against its own manifest with the proper public or private scope, metadata, and content type. A copied course may already refer to assets from another course through a valid prior copy. Follow the existing material-level authorization and retention rules for those references.
- Reuse the existing ordered PDF and video locks and validate the locked rows before writing references. Associate a failed lock with every affected source material in the attempted copy. Check database readiness during preview. A later storage serving failure follows the existing media recovery path. Multiple affected materials may point to the same missing object, so report their locations while retaining just one underlying metadata query. Preview performs no storage fetches or per-object probes.
- Resolve structured references using the source snapshot and the destination ID map. An out-of-scope target produces a blocker on the referring item. Free-form links remain authored content and follow current sanitization and access rules.
- Preserve existing rules for reading private answers, solution assets, captions, and media after copying or deleting the source. A copy grants access through its destination material and normal authorization checks.

## Admin workflow and API diagnostics

Keep both current entry points, the source revision, the title field, and the destination navigation after success. Group diagnostics by module, lecture, and material in outline order. Show each item’s material type and effective source visibility, including hidden ancestors. Display specific instructions in English and Korean. Keep the form title and selected course when a repair or refresh is required.

Each diagnostic carries a severity, stable reason code, source material ID, and an allowlisted field category when useful. Keep preview blockers compatible with the existing response and add warning data. Use IDs to join the existing module and lecture context. Deduplicate by material, severity, reason, and field, with stable ordering for multiple issues on one item. If the commit discovers a new problem, return the same safe issue shape for affected items with their source location context, under the existing `LIBRARY_IMPORT_CONTENT_INVALID` code. Use typed error data and keep the generic translated fallback for older responses or unexpected failures. Example messages include “Select a valid correct option,” “Restore the image in the answer explanation,” “Wait for the video to finish processing, then refresh,” and “Choose a supplementary PDF from this course.”

Use the existing authorized course review route and editor links where available. Offer an explicit refresh after repair and preserve the existing back navigation to source selection. Give the module, lecture, material, and field as the navigation fallback. If the user can review but cannot edit, direct the repair to an authorized academy editor. The copy dialog only reads the source. Warnings remain visible and allow draft creation. Blockers disable it. A successful refresh after repair updates the diagnostics without resetting the title.

Use allowlisted messages and issue codes in the API and any logs. Include enough identifiers to correlate a validated source revision with an issue. Keep raw Zod errors, answer values, solution code and paths, hidden test inputs, authored HTML, storage keys, signed URLs, and learner data out of diagnostics, audit details, and logs. The authorized preview keeps its existing course and material titles and structural metadata.

## Transactions, retries, and reads

- Preview reads a repeatable snapshot. Import reauthorizes, takes the existing locks, checks the requested source revision, revalidates current content and readiness, and copies from that transaction’s snapshot. Handle a changed course through the existing refresh flow. Asset readiness can change without a course revision bump and must be checked again.
- Retain case-insensitive destination title checks and the lock shared by create, rename, and import. Report a title conflict separately so the admin can edit the title. Keep bounded retries for transient database conflicts and idempotent receipt replay after a lost response. Retry the same source, revision, and title with the same request key after an ambiguous result. A changed request gets a fresh key. Keep the existing protection against key reuse by another actor or for different inputs.
- Keep outline reads structural and lightweight. Load only validation inputs with separate batched subtype reads, and use aggregate or projected facts for presence, size, and reference checks where possible. Private authored fields needed for validation stay server-side. Keep full reference solutions, test payloads, learner starter code, and private project files out of ordinary outline and preview responses. Where detailed private validation is needed during preview, select only the fields the rule consumes. Reuse the required values from the full write snapshot during import.
- Use a fixed set of batched statements by relation or asset kind, with independent reads in parallel. Match preview relation coverage to the copier even when an attachment sits on another material type. Measure the current and revised query counts for a small and large course with the same material mix. Assert that counts stay constant as materials, references, and tests grow. Count statements on disposable Docker PostgreSQL through `COVE_INTEGRATION_DATABASE_URL` and record any changed counts in the implementation commit.
