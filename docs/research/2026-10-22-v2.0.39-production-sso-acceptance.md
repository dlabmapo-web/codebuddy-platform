## Findings and acceptance boundaries

These successful Chrome workflows do not establish that every live interaction works across browsers:

- The independent Safari attempt reached the OS account selector and returned to Cove, but the authenticated page remained loading/blank. The native browser could still render the existing GitHub tab. No console diagnosis or root cause was established. The extra Safari test tab was closed, leaving its existing tabs intact.
- Both staff class views reached Live, but simultaneous Student/Teacher or Student/Manager typing, positive online/solving count changes, and the complete help-request/claim/resolve loop were not completed in this production pass. Earlier disposable automated tests cover these flows; they are not a substitute for live acceptance.
- No real video upload, transcoding/playback, email delivery, scheduling, load testing or additional-campus workflow was run here.

Minor UI findings observed during the pass:

1. Native short-answer materials still use the generic “Written response” type label in the course list/tree, although the correct short-answer configuration and automatic grader are active.
2. A saved PDF title update could remain stale in an already cached course tree until a fresh course load. The standalone heading and subsequently loaded course displayed the saved title.
3. A revoked Teacher monitoring URL displays “This academy is not available”, which is misleading because that Teacher still belongs to the academy and can open their other assigned class.
4. The authoring console reports duplicate Tiptap `link`/`underline` extension warnings. They did not block the tested saves.
