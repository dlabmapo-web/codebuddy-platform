The approved multi-campus implementation is merged into v2 at `2f236e77eb17ae1a7b3afcdc25001eee6cee9846`. Its [exact-commit CI](https://github.com/dlabmapo-web/codebuddy-platform/actions/runs/41786042092) passed all ten jobs, including builds, typechecks, lint, tests, deployment checks and eight image scans.

## Why v2.0.47 was not deployed

The [v2.0.47 publication run](https://github.com/dlabmapo-web/codebuddy-platform/actions/runs/41786867585) built/published the images but failed all eight scan jobs while installing Trivy. The protected deploy job was skipped. Production remained on v2.0.46; no deployment or application rollback occurred.

Logs show Trivy's installer selecting v0.70.0 and exiting with curl code 6 before running a scan. The [v0.70.0 installer](https://github.com/aquasecurity/trivy/blob/v0.70.0/contrib/install.sh) downloads through `get.trivy.dev`. An independent DNS lookup could not resolve that host, while github.com resolved. Curl documents code 6 as [a host resolution failure](https://curl.se/libcurl/c/libcurl-errors.html). This evidence indicates an installer transport failure, not a vulnerability finding.

The deployment guide requires immutable, unused release tags. v2.0.47 is retained as a failed, undeployed attempt; the corrected candidate uses v2.0.48.

## Scanner installation correction

CI and release now install the same Trivy v0.70.0 binary directly from the official GitHub release asset, verify its pinned SHA-256, and add the verified executable to the job's PATH before invoking the existing pinned Trivy action.

- Official asset: `trivy_0.70.0_Linux-64bit.tar.gz` from the [v0.70.0 release](https://github.com/aquasecurity/trivy/releases/tag/v0.70.0).
- SHA-256: `8b4376d5d6befe5c24d503f10ff136d9e0c49f9127a4279fd110b727929a5aa9`, matching both GitHub asset metadata and the published checksums file.
- `skip-setup-trivy: true` skips only the unavailable upstream installer; the preceding step installs and executes the verified scanner. Scans remain required, at the same CRITICAL severity, ignore-unfixed policy and exit code 1. No `continue-on-error`, scanner downgrade or database-update bypass was introduced.
- Two local tests reject tampered content and transport failure before installation or PATH modification. Both passed.
- The installer was also executed with an isolated explicit directory under production's private release-state folder. The verified Linux binary reported `Version: 0.70.0`; no service configuration or application container was changed.
- Deployment configuration validation and shell syntax checks passed. The final candidate still requires all ten exact-commit CI jobs, eight publication scans and human Production approval.
