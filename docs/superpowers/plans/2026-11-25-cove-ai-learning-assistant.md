# Implement the Cove AI learning assistant

Work through these steps in order. The first usable slice is one class solving “Print Hello” in Python. The [product design](../specs/2026-11-25-cove-ai-learning-assistant-design.md) explains the experience and the [data contract](../specs/2026-11-25-cove-ai-learning-assistant-data.md) defines what each write means.

| Order | Change | Check before moving on |
| --- | --- | --- |
| 1 | Create a synthetic course with an AI-enabled automatic exercise, an empty hint list and one public case. Add a disabled exercise and an exam with similar content as controls. Use a fake model with deterministic replies for development. | The existing grader accepts both quote styles for `Hello` and rejects `hello`. Record baseline SQL counts and grading latency. |
| 2 | Add nullable admission context references, occurrence/pattern links, versioned notes and private help deliveries with the uniqueness rules in the data contract. Extend the narrow [admission reader](../../../packages/api/src/learn/submission-admission-read.ts) to project enablement and the fields needed to freeze public context. Handle old submissions without a context. | A text-only edit creates a new context. Copying a course gives it a separate bank. Author saves and imports preserve AI notes. |
| 3 | Add the independent capture worker and batch reconciliation. Start with a generic “unclassified” occurrence and the deterministic case-only rule. Create the first matching feedback and hint slots automatically. | Submit ten genuine failures with the model stopped and nobody clicking Help. Find ten occurrences and one pattern. Start the worker again and verify missing analysis catches up without duplicate notes. |
| 4 | Add typed learning operations in the [shared oRPC contract](../../../packages/shared/src/api/orpc/learn.contract.ts) and implement the server adapter. Resolve current access once, project permitted evidence, retrieve notes, validate the reply and persist the delivery. A cache hit fills an active note with this student's values. A miss can use the model or a reviewed fallback. | Two students can receive the same teaching advice without sharing private work. A repeated click with the same request ID has one delivery and does not skip a hint. |
| 5 | Expose assistant availability in the existing student workspace bootstrap. Update the [hint dialog](../../../packages/web/src/components/workspace/hints-dialog.tsx) and its parent to work with an empty authored list. Put **Explain my result** beside the failed final verdict in the learner result panel. Respect staff use of the shared components. Add Korean and English strings, keyboard focus, pending and retry states. | A student can complete the full workflow with the keyboard. Grading, authored hints and navigation still work during a model outage. |
| 6 | Add optional edit/retire actions to exercise authoring for people who already have edit permission. Link the next attempt for evaluation and add aggregate counters for capture coverage, unknown cases, model time and note hits. | A correction is returned on the next new request, survives a subsequent author save and wins a race against a stale generation job. |
| 7 | Run the [pilot checks](../../qa/2026-11-25-cove-ai-learning-assistant.md). Start with one academy and an isolated model endpoint. Expand to other enabled automatic exercises and C/C++ once public compile diagnostics, multi-file visibility and language-specific teaching examples pass the same checks. | Compare pilot performance against baseline under simultaneous grading and assistance. Enable a larger cohort only when both the grading and feedback checks pass. |

## What to take from DocQuery

Paths below are relative to the separate `docquery` checkout. Adapt these patterns in Cove so the two applications can deploy independently.

| DocQuery source | Reuse in Cove |
| --- | --- |
| `packages/doc/src/model/model.service.ts`, `buildLCModel` | Keep endpoint, credentials and model name behind one server-side interface. Put provider settings and bounded concurrency in Cove's runtime configuration. Avoid copying verbose prompt logging. |
| `packages/doc/src/sendMsg/sendMsg.profile.semanticV1.service.ts` | Follow the order of operations: establish access, retrieve relevant information, construct the prompt and call the model. Replace document chunks and chat history with an exercise context, public evidence and matched notes. |
| `service/eval/deepeval_runner.py` | Reuse the example/expected answer/actual answer/context evaluation format. Add action, language, allowed observations and unacceptable claims. A teacher can score the synthetic pilot set without running DocQuery's hosted evaluator. |

The known exercise ID and rule key make PostgreSQL lookup a good fit for v1. Keep document ingestion, embeddings and OpenSearch outside the first release. For the discussed local pilot, benchmark Qwen3.5-4B via Ollama on a development machine. Treat the model as replaceable. The four-vCPU AWS host's ability to serve a classroom while grading remains a measurement to make in staging.

## Extend collection to practice runs

After the submitted-attempt pilot, add a separate observation source for student-initiated public sample checks and explicit **Run** actions. [Server sample checks](../../../packages/api/src/judge/sample-check.store.ts) expire in Redis. Persist a small assistant observation at successful terminal transition for a genuine failed public comparison or a known runtime/compile failure. Pair the Redis transition with a recoverable event in the same atomic operation, then consume it idempotently by check ID. Retain only the allowed evidence required by the assistant. Keep sample history separate from official submissions, grades and points.

For browser-only runs, send a bounded observation tied to an owned solve session and a unique run ID. Label it client-reported. A browser error can inform that student's next hint. Promote a pattern only when independently supported by a trusted rule and evidence. A free run without expected output can show a runtime failure, but cannot establish that an answer was logically wrong. Report collection coverage separately for official, server-sample and browser sources.
