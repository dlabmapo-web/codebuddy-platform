## Findings

### Important — Local host/bin contents can leak into the production artifact

**Locations:** `packages/grading-runtime/Dockerfile.broker:14-16`, especially the new overlay at line 15; `packages/grading-runtime/package.json:25`.

The build stage first copies the entire local `packages/grading-runtime` directory, then copies `/native/bin` over its existing `host/bin`. Docker COPY overlays directory contents; it does not remove destination-only files. The package now includes all of `host/bin`. Root `.dockerignore` has no exclusion for this directory, and there is no broker-specific Docker ignore file. The native stage's `make clean` only cleans `/native/bin`, not the separate Node build-stage destination.

Consequently, a developer who has produced `host/bin/fixtures` (the Makefile explicitly supports it), or left another local binary/build file there, can build a broker artifact that contains it. The newly built attestor/client can have the right manifest hashes while the extra file is still deployed. This violates Task 1's requirement that the runtime contain only the two native tools, manifest and licenses and exclude fixtures/build/vendor source. It also makes the artifact depend on ignored local build output. The clean current artifact does not establish this source invariant.

I independently inspected the two COPY operations, package allowlist and applicable Docker ignore rules. The controller additionally reported a focused, reversible synthetic `pnpm pack` probe in which `host/bin/cove-packaging-canary` appeared in the tarball; that probe was controller evidence, not a test rerun by this reviewer.

**Required fix:** Prevent local generated `host/bin` from entering the broker build context, or replace the build-stage destination before copying the trusted native output; also make package/runtime contents sufficiently explicit that test output cannot be accidentally distributed. Add a focused canary regression that starts with an extra local host/bin file and confirms it is absent from the packaged/extracted broker runtime. Preserve the existing strict self-workspace-symlink handling.

## Source assessment

- **Schemas and paths:** The application grammar gate rejects unsupported JSON syntax before bounded jsmn tokenization; exact field decoding rejects duplicates, unknown/missing fields and unsafe integers. Config/proof readers reject embedded NUL, oversize/truncation and concurrent metadata changes. Component-wise directory-FD walks use O_NOFOLLOW, immutable ownership/mode checks and single-link regular files. Canonical executable paths are checked against the actual proc executable, not the installation symlink. The daemon config remains a configured argument rather than introducing an unauthorized root-ownership policy.
- **Namespace-aware trust:** The client treats overflow UID as a representation, excludes its own nonroot UID, verifies root-anchored immutable paths and authenticates the helper's root-validated config hash. The initial-userns helper checks the root-pinned self namespace tuple. Root bootstrap independently checks PID1/helper namespace and actual helper executable; normal mode does not recursively access protected helper exe/ns. These still depend on Task 2 providing the documented trusted mount/launch/configuration context.
- **Live identity:** Daemon attestation uses a fresh Unix connection, kernel SO_PEERCRED and a held pidfd, current UID checks, final-parenthesis proc stat parsing, exact config argument matching and strict cgroup ancestry. Executable/path/dev/inode/hash, process start, cgroup and socket incarnation are compared across observations. Normal client binds its own executable to proof, checks live helper PID/UID/GID/start/socket/cgroup, nonce, instance, boot and config, then rechecks config/proof bytes and liveness. A changed valid daemon is returned for the broker's frozen comparison, as documented; lifecycle enforcement remains Task 2.
- **Protocol and deadlines:** One fixed 48-byte request has no target fields. Request half-close and response EOF make trailing data rejectable; payload bounds keep the complete response within 8192 bytes. Socket polling and IO use the same per-exchange monotonic deadline, and read/hash loops check it. Server serves one accepted connection serially, with backlog 3 documenting Linux's four pending queue slots. Real execution must still confirm deadline and queue behavior.
- **Policy:** Main rejects arguments, clears environment, closes inherited FDs >=3, verifies identity, binds a fresh socket and requires NNP/dumpable0/seccomp before listen. The AMD64 filter has a wrong-architecture kill, x32 rejection, default EPERM and correctly bounded special-rule jumps. Read-only openat, non-executable mmap, restricted Unix socket creation and connected sendto rules preserve the stated post-ready restrictions; exec/fork/clone, namespace changes, ptrace/process writes, mprotect/prctl, FD export and unlisted syscalls are denied. The fixture shares production policy without adding a production test mode. Static libc startup precedes clearenv, and PROTOCOL correctly assigns launcher environment sanitization to Task 2.
- **Build/workflow:** Compiler image and native link flags are pinned, and manifest generation verifies vendor inventory, static ELF properties, compiler/runtime-library identities and notices. No existing broker hardening/resource/daemon/guest policy was changed in this package. The new real-AMD64 native_contracts prerequisite uses the required constrained container and has no unsupported-platform skip; its outcome is included in the always-run fallback and associated contract tests. The packaging issue above is the remaining concrete source defect.
